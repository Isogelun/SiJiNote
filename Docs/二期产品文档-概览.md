## 0. 本文怎么写、怎么用

1. 本文是二期范围的**清单和边界**，不是可直接开发的规格。评审通过后再按一期文档的五段式（目标 / 界面元素 / 操作流程 / 规则与边界 / 异常与提示）逐模块展开。
2. 每个模块只回答三个问题：**做什么、不做什么、卡在哪里**。
3. 优先级只在二期内部比较：P0 = 二期必须交付；P1 = 争取；P2 = 允许推到三期。
4. 功能点编号 `M<模块>-<序号>`，评审时直接引用「M3-2」。

## 1. 二期定位

**一句话**：把一期「能用」变成「好用、可交付给团队、内容带得走」。

一期交付的是一条单用户最小闭环：登录、建库、写笔记、批注、回收站。它刻意砍掉了三块东西，二期要补回来：

| 砍掉的东西 | 后果 | 二期对应模块 |
| --- | --- | --- |
| 编辑器只做整篇编辑，缺图片、表格、大纲 | 长文写作体验弱，用户会转回 Typora / 语雀 | M2 编辑器能力 |
| 没有导入导出与分享 | 内容进得来出不去，产品无法对外传播 | M5 迁移、M6 分享 |
| 只有普通账号，无企业形态 | 无法卖给团队，只能个人自用 | M7 企业与部署 |

**三个目标（建议作为二期验收口径）**

1. 写作不中断：图片、表格、大纲可用，长文档不卡。
2. 内容可迁移：Markdown 双向无损，能从语雀 / Notion 搬进来。
3. 能给别人看：单篇可只读分享，团队可邀请成员。

> 具体指标（如图片插入成功率、导入成功率、分享打开率）待 M1 排期时补，不用一期指标口径硬套。

## 2. 二期范围总表

| 模块 | 主要功能 | 优先级 | 依赖 / 前置 |
| --- | --- | --- | --- |
| M0 一期 P1 平移项 | 搜索、导出（导入可选）、分享基础版 | P0 | 一期未交付则直接进二期 |
| M1 编辑器内核 | 块级预览、块模型重构 | P0 | 编辑器需先有块结构，影响批注锚点 |
| M2 编辑器能力 | 图片、表格、大纲、行内样式补齐 | P0 | M1 |
| M3 批注增强 | 跨段批注、失效重定位、状态与颜色 | P1 | M1 |
| M4 组织能力 | 拖拽排序/移动、多层文件夹、批量操作 | P1 | 目录树改版 |
| M5 迁移与备份 | 图片附件导入导出、PDF/Word 导出、第三方迁移 | P1 | M2（图片先落地） |
| M6 分享与协作 | 权限细分、评论、访问统计 | P1 | 权限模型 |
| M7 企业与部署 | 企业账号、子账号与角色、独立部署 | P0 | 账号体系重构 + 部署包 |
| M8 AI 助手 | 右侧 AI · Copilot | P2 | 模型选型与成本待定 |
| M9 平台与多端 | 存储配额、多端同步、国际化 | 待确认 | 服务端能力 |

> M0 不是「新功能」，是把一期 P1 的欠账补上。它排在最前，因为搜索和导出是用户最先抱怨的两个缺口。

## 3. 分批交付建议

二期不建议一次性全上，按下面四批走，每批可独立发布：

| 批次 | 内容 | 判断标准 |
| --- | --- | --- |
| 批次 A：补齐 | M0 + M1 | 一期用户不再需要外部工具 |
| 批次 B：写作 | M2 + M3 + M4 | 长文写作体验达到 Typora 的 80% |
| 批次 C：流动 | M5 + M6 | 内容可进可出可分享 |
| 批次 D：商业化 | M7 | 能签第一个团队客户 |

M8 / M9 不排进固定批次，按资源插入。

## 4. 各模块大概内容

### M0 一期 P1 平移项

| 编号 | 功能点 | 说明 |
| --- | --- | --- |
| M0-1 | 全库搜索 | 标题 + 正文，跨知识库；一期规格可直接复用 |
| M0-2 | 导出 Markdown | 单篇 + 全部打包 zip |
| M0-3 | 导入 Markdown | 可与 M5 合并，避免做两遍 |
| M0-4 | 分享基础版 | 只读链接 + 有效期，不含权限细分 |

**边界**：不做离线搜索、不做搜索批注内容（归 M6 / M3）。

### M1 编辑器内核

| 编号 | 功能点 | 说明 |
| --- | --- | --- |
| M1-1 | 块模型 | 正文解析为块序列，块带类型、源码区间、纯文本 |
| M1-2 | 块级预览 | 光标所在块显示源码，其余块渲染最终样式（类 Obsidian） |
| M1-3 | 块内编辑事务 | 撤销栈、格式应用、粘贴统一走块级事务 |

**边界**：只改渲染与编辑内核，不改存储格式——正文仍是 Markdown 单一存储，块是解析产物。

**风险**：批注锚点目前基于段落序号 + 签名，块模型重构后锚点口径要跟着改，两件事必须同批做。

### M2 编辑器能力

| 编号 | 功能点 | 说明 |
| --- | --- | --- |
| M2-1 | 图片 | 插入、粘贴、拖拽；缩放；走上传与附件存储 |
| M2-2 | 表格 | 列对齐；单元格合并不支持 |
| M2-3 | 大纲栏 | H1–H3，点击跳转，滚动同步高亮 |
| M2-4 | 行内样式补齐 | 下划线、字体颜色、荧光笔、居中 |
| M2-5 | 字体字号 | 从「正文/H1–H3」扩展为可选字号（待确认边界） |

**边界**：图片与表格会带来导出、分享、附件配额三个下游改动，M2 交付时必须同步评估 M5 / M9。

### M3 批注增强

| 编号 | 功能点 | 说明 |
| --- | --- | --- |
| M3-1 | 跨段批注 | 一期仅单段，二期放开，需要块区间锚点 |
| M3-2 | 模糊重定位 | 精确失败后按相似度匹配，阈值待定 |
| M3-3 | 批注状态 | 已解决 / 未解决，已解决沉底 |
| M3-4 | 批注颜色 | 多色区分类型 |
| M3-5 | 批注搜索 | 搜索结果包含批注说明 |

**边界**：仍不做多人批注（归 M6）。

### M4 组织能力

| 编号 | 功能点 | 说明 |
| --- | --- | --- |
| M4-1 | 拖拽排序 | 同级拖拽，sort_index 已有一期基础 |
| M4-2 | 拖拽移动 | 跨文件夹、跨知识库 |
| M4-3 | 多层文件夹 | 从一层放开到不限层（或限 5 层，待确认） |
| M4-4 | 批量选择 | 批量移动、删除、收藏 |
| M4-5 | 复制 / 剪切 / 粘贴 | 笔记跨库复制 |
| M4-6 | 知识库排序 | 自定义顺序、置顶 |

**边界**：多层文件夹会连带改移动端目录树交互，需单独评估。

### M5 迁移与备份

| 编号 | 功能点 | 说明 |
| --- | --- | --- |
| M5-1 | 图片与附件导入导出 | 相对路径重写、缺失图片提示 |
| M5-2 | PDF / Word / HTML 导出 | 排版保真度是难点，先做 PDF |
| M5-3 | 第三方迁移 | 语雀、Notion 导出包解析 |
| M5-4 | 定时备份 | 云端整库快照，频率与保留策略待定 |

**边界**：M5-3 按平台逐个评估，不承诺「全平台一键迁移」。

### M6 分享与协作

| 编号 | 功能点 | 说明 |
| --- | --- | --- |
| M6-1 | 分享权限细分 | 只读 / 可评论 / 可编辑 |
| M6-2 | 评论 | 段落级评论，与批注区分 |
| M6-3 | @提及与通知 | 依赖通知通道（邮件 / 站内） |
| M6-4 | 访问统计 | 打开次数、来源，需考虑隐私口径 |
| M6-5 | 多人协同编辑 | 见下方风险 |

**风险**：M6-5 是二期最大不确定项。实时协同需要 CRDT 或 OT + 服务端常驻连接，工作量可能超过前面所有模块之和。**建议二期只做「多端同步 + 冲突提示」，实时协同推三期**，这一条需要产品拍板。

### M7 企业与部署

| 编号 | 功能点 | 说明 |
| --- | --- | --- |
| M7-1 | 企业账号 | 主账号 + 子账号，登录页放开企业登录方式 |
| M7-2 | 角色与权限 | 管理员 / 成员；知识库级权限待定 |
| M7-3 | 成员邀请 | 邮箱邀请、加入流程 |
| M7-4 | 独立部署 | 服务端初始账密 + 部署 UID 登录；交付部署包与升级方案 |
| M7-5 | 账号安全 | 找回密码、修改密码、邮箱验证 |

**依赖**：M7 要求账号体系从「单用户」扩成「组织 → 成员」，数据表要加 tenant / org 维度，越晚做改动越大。**这是二期最该先定的事**。

### M8 AI 助手

| 编号 | 功能点 | 说明 |
| --- | --- | --- |
| M8-1 | 右侧 Copilot 面板 | 类 VSCode 侧栏，可问可改 |
| M8-2 | 选中文字的操作 | 续写、改写、摘要、翻译 |
| M8-3 | 基于笔记的问答 | 检索当前库内容后回答 |

**边界 / 待确认**：模型来源（自建 / 云 API）、是否用用户内容训练、成本由谁承担、企业版是否允许关闭。**这几条没定之前不开工**。

### M9 平台与多端

| 编号 | 功能点 | 说明 |
| --- | --- | --- |
| M9-1 | 存储空间配额 | 侧边栏「存储空间」放开，展示用量 |
| M9-2 | 多端同步 | 桌面 / Android / iOS / Web 同步策略 |
| M9-3 | 国际化 | 文案抽离，先做简体中文 + 英文 |
| M9-4 | 性能兜底 | 1 万篇列表、10 万字文档 |

**待确认**：M9-2 是否属于二期。一期是单端假设，一旦多端同时在线，冲突处理必须从「弹窗二选一」升级。

## 5. 技术前置与风险

| 风险 | 影响 | 建议 |
| --- | --- | --- |
| 块模型重构（M1）牵动批注锚点 | 批注可能全体失效 | M1 与 M3 同批，锚点方案一起定 |
| 实时协同（M6-5）成本不可控 | 拖垮整批交付 | 二期只做同步 + 冲突提示，协同推三期 |
| 企业账号（M7）改数据模型 | 越晚改代价越大 | 二期启动第一件事就定 org 维度 |
| 图片与附件（M2-1）需要存储 | 牵连配额、导出、分享 | 先定存储方案再动编辑器 |
| AI（M8）合规与成本 | 无法承诺交付 | 单独立项，不占二期主线排期 |

---

## 6. 二期不做（推三期）

- 实时多人协同编辑
- 插件 / 开放 API / 第三方集成
- 移动端离线全量同步（只做按需拉取）
- 团队知识库模板市场
- 桌面端全局快捷采集（剪藏）
- 端到端加密
